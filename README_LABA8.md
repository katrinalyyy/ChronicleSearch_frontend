# Лабораторная работа: Межсервисное взаимодействие, асинхронность, внедрение Real-time web

## Цель работы

Разработать систему межсервисного взаимодействия с асинхронной обработкой данных и реализацией механизма Real-time обновлений через short polling для отображения актуальных статусов заявок.

## Архитектура системы

### Основной сервис (Go)
Основной веб-сервис на Go, реализующий REST API для работы с заявками на спектроскопический анализ. Включает:
- Авторизацию пользователей и модераторов
- Управление заявками (создание, формирование, завершение)
- Управление пигментами
- Взаимодействие с асинхронным сервисом через HTTP

### Асинхронный сервис (Python/Django)
Выделенный сервис на Python/Django для выполнения отложенных вычислений:
- HTTP-метод для асинхронной обработки заявки
- Расчет точности спектрального анализа и процентов пигментов
- Задержка выполнения 5-10 секунд
- Возврат случайного или вычисляемого результата
- Взаимодействие с основным сервисом через HTTP без прямого доступа к БД

## Основные компоненты

### Межсервисное взаимодействие

#### 1. Асинхронный сервис
- **Эндпоинт**: `POST /api/async/process-analysis`
- **Функциональность**: Принимает ID заявки, выполняет вычисления с задержкой 5-10 секунд
- **Результат**: Вычисление точности анализа и обновление процентов пигментов в м-м таблице
- **Реализация**: Python/Django сервис, работающий на отдельном порту

#### 2. Основной сервис
- **Эндпоинт для получения результатов**: `POST /api/spectrum-analysis/:id/update-results`
- **Авторизация**: Псевдо-авторизация через ключ-токен (8 байт) в заголовке запроса
- **Функциональность**: Принимает результаты от асинхронного сервиса и обновляет данные в БД
- **Проверка токена**: Простая проверка совпадения константного ключа

### Разделение логики завершения заявки

При завершении заявки (`PUT /api/spectrum-analysis/:id/complete`):
1. **Основной сервис**: Обновляет статус заявки на "completed"
2. **Асинхронный сервис**: Вызывается для выполнения расчетов
3. **Результаты**: Асинхронный сервис вызывает метод основного сервиса для внесения результатов

### Поле в м-м таблице

В таблице `spectrumAnalysis_pigment`:
- Поле `percent` (float64) — заполняется асинхронно
- При создании заявки поле пустое (0)
- Асинхронный сервис рассчитывает и заполняет проценты для каждого пигмента

### Поле в списке заявок

В GET списка заявок (`GET /api/spectrum-analysis`) добавлено поле:
- `processed_pigments_count` (int) — количество записей м-м, в которых поле `percent` заполнено (не равно 0)
- При формировании заявки = 0
- После асинхронной обработки увеличивается до количества пигментов в заявке

## Real-time обновления (Short Polling)

### Реализация на фронтенде
- Список заявок обновляется автоматически через short polling
- Интервал опроса: 3-5 секунд
- Обновление статусов и счетчика обработанных пигментов в реальном времени

### Backend
- Эндпоинт `GET /api/spectrum-analysis` возвращает актуальные данные
- Включает поле `processed_pigments_count` для каждой заявки

1. **Через Insomnia**: Вызвать `GET /api/spectrum-analysis` для получения списка заявок
2. **HTTP-метод асинхронного сервиса**:

## Технические детали

### Псевдо-авторизация
- Ключ-токен: константа на 8 байт (например, `"secret12345678"`)
- Передается в заголовке `X-API-Key`
- Проверка в методе `update-results` через простое сравнение строк

### Асинхронная обработка
- Задержка: 5-10 секунд (случайная или фиксированная)
- Результат: вычисление процентов пигментов на основе спектральных данных
- Всегда записывается результат (успех/неуспех), ошибки программы обрабатываются отдельно

### Обновление данных
- Асинхронный сервис НЕ обращается к БД напрямую
- Все обновления через HTTP API основного сервиса
- Метод `update-results` защищен псевдо-авторизацией

## CORS (Cross-Origin Resource Sharing)

CORS настроен в основном сервисе для разрешения запросов с любого источника.

### Расположение настройки
**Файл**: `cmd/colorLex/main.go` (строки 80-92)

```go
// Добавляем CORS middleware
router.Use(func(c *gin.Context) {
    c.Header("Access-Control-Allow-Origin", "*")
    c.Header("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
    c.Header("Access-Control-Allow-Headers", "Origin, Content-Type, Content-Length, Accept-Encoding, X-CSRF-Token, Authorization")

    if c.Request.Method == "OPTIONS" {
        c.AbortWithStatus(204)
        return
    }

    c.Next()
})
```

### Параметры CORS
- **Access-Control-Allow-Origin**: `*` — разрешает запросы с любого домена
- **Access-Control-Allow-Methods**: GET, POST, PUT, DELETE, OPTIONS
- **Access-Control-Allow-Headers**: заголовки, включая Authorization для JWT токенов
- **OPTIONS**: предварительные запросы обрабатываются сразу (204 No Content)

### Демонстрация
1. Открыть файл `cmd/colorLex/main.go` в IDE
2. Показать блок настройки CORS middleware (строки 80-92)
3. Объяснить, что `*` разрешает запросы с любого домена (включая фронтенд на другом порту)
4. В браузере (DevTools → Network) проверить заголовки ответа — должны содержать CORS заголовки
